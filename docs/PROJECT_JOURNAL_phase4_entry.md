## Phase 4 — Baseline Modeling (2026-08-15)

### Objective
Establish a leakage-safe feature/label dataset, a chronological
train/validation/test split, naive baselines, and a first real ML model
(Logistic Regression), evaluated on VALIDATION only -- before touching
anything MLOps-heavy (MLflow, Airflow) or a stronger model class.

### Steps completed
1. **EDA** -- confirmed `days_since_last_detection` cap of 90 is appropriate,
   selected `future_fire_7d` as the primary modeling target (3d/14d kept for
   later comparison, not modeled now), confirmed weather features are 0%
   missing, decided FRP NaNs represent "no detection" and should be filled
   with 0 rather than treated as unknown.
2. **`ml/dataset.py`** -- feature/label assembly. Joins the Phase 3 cell-day
   dataset with `targets_h7.parquet`, imputes FRP NaN -> 0, verifies no
   unexpected missingness remains (raises rather than silently training on
   dirty data), drops end-of-period null-labeled rows with the exact count
   logged (2,261 dropped on the real dataset -> 941,545 usable rows).
3. **`ml/split.py`** -- chronological split, no randomness. TRAIN
   (2018-2022) / VALIDATION (2023) / TEST (2024-2025), with an explicit
   `validate_split_partition()` check for coverage, no index overlap, and
   correct date ordering across all three splits. Real sizes: train
   589,798 / validation 117,895 / test 233,852.
4. **`ml/baseline.py` + `ml/train.py`** -- three baselines sharing one
   fit/predict/predict_proba contract: `MajorityClassBaseline` (ignores
   features entirely, the floor), `PersistenceBaseline` (predicts based on
   same-day `fire_count > 0`, a domain-informed second floor), and
   `LogisticRegressionBaseline` (`class_weight="balanced"`, no tuning). All
   three are trained on TRAIN only -- validation/test are never touched
   during fitting. Feature selection is enforced through one shared
   `_select_features()` function so `cell_id`/`date` structurally cannot
   reach any model, regardless of what extra columns the caller's
   DataFrame carries.
5. **`ml/evaluate.py`** -- evaluates all three fitted models on VALIDATION
   ONLY (precision, recall, F1, ROC-AUC, PR-AUC, confusion matrix). TEST is
   never evaluated and no model selection has occurred -- that's
   deliberately deferred past Phase 4.

### Real results
See `docs/phase4-baseline-results.md` (generated by running
`PYTHONPATH=. python -m ml.evaluate` against the real data) for the actual
VALIDATION metrics and the strongest-baseline conclusion.

### Decisions
- Class imbalance (~18.45% positive on the 7-day horizon) is handled via
  `class_weight="balanced"` for now -- no resampling, no threshold tuning.
  Both are explicitly deferred past Phase 4.
- TEST is not evaluated anywhere in Phase 4. It stays genuinely held out
  until a model is actually chosen for further development (Phase 5+).
- No MLflow/XGBoost/LightGBM/Airflow/Streamlit/AI layer added -- Phase 4's
  scope was proving the dataset can support a real model with a defensible
  floor to beat, not building out the full MLOps stack.

### Testing
123/123 tests pass (`PYTHONPATH=. pytest -q`), including a new end-to-end
integration test (`tests/test_phase4_integration.py`) wiring
`ml.dataset -> ml.split -> ml.train -> ml.evaluate` together on synthetic
data shaped like the real Phase 3 output, to catch cross-module breakage
that per-module unit tests wouldn't necessarily surface.

### Next (Phase 5, not started)
Model comparison beyond Logistic Regression (e.g. Random Forest / gradient
boosting) if the baseline results justify it, proper experiment tracking
(MLflow), and only then orchestration (Airflow) and the AI layer -- in that
order, per the original roadmap.
