## Phase 6 — Threshold & Calibration Analysis (VALIDATION only)

### Objective
Determine each model's F1-optimal decision threshold and assess probability
calibration quality (Brier score, 10-bin reliability curve, ECE) for the
two Phase 5 tree models, using VALIDATION only. Not a search for a new
model, not a final decision -- an analysis step between "which model looks
best at an arbitrary 0.5 cutoff" (Phase 5) and an actual locked candidate.

### Data discipline
- **TRAIN** -- model fitting only (`fit_models_for_phase6`).
- **VALIDATION** -- threshold sweep, F1-optimal threshold selection, and
  all calibration analysis (`analyze_model_on_validation`).
- **TEST** -- not evaluated, scored, or used in any calculation anywhere in
  this phase. `analyze_model_on_validation` has no `test_df` parameter.
- No hyperparameter tuning. No XGBoost/LightGBM. No MLflow yet.

### Reused unchanged
`ml/dataset.py`, `ml/split.py`, `ml/models.py` (`RandomForestModel`,
`GradientBoostingModel`), `ml/features.py`. No modifications to Phase 4/5
modeling files were required for Phase 6.

### Threshold methodology
`ml/threshold.py`: `evaluate_threshold(y_true, y_prob, threshold)` computes
precision/recall/F1/positive-rate/confusion-matrix counts at one threshold
(`y_prob >= threshold`). `sweep_thresholds()` sweeps 0.05-0.95 in fixed
0.05 steps (19 thresholds), deterministically. `find_f1_optimal_threshold()`
returns the sweep result with the highest F1, breaking ties by preferring the
LOWER threshold.

### Calibration methodology
`ml/calibration.py`: `compute_brier_score()` measures mean squared error
between predicted probability and true outcome. `compute_calibration_curve()`
bins VALIDATION predictions into 10 fixed-width bins over [0, 1] and reports
mean predicted probability vs. observed positive rate per bin.
`compute_ece()` is the sample-count-weighted average calibration gap across
those same bins.

### Real results (VALIDATION only, TEST untouched)

| Model | Default F1 | Optimal Threshold | Optimal F1 | ROC-AUC | PR-AUC | Brier | ECE |
|---|---:|---:|---:|---:|---:|---:|---:|
| Random Forest | 0.7082 | 0.65 | 0.7307 | 0.9406 | 0.8156 | **0.087495** | **0.104211** |
| Gradient Boosting | 0.6932 | **0.70** | **0.7340** | **0.9417** | **0.8176** | 0.095452 | 0.123672 |

At the validation-selected thresholds, Gradient Boosting has the slightly
higher F1 (0.7340 vs. 0.7307) and slightly higher PR-AUC (0.8176 vs. 0.8156).
Random Forest has better Brier and ECE calibration metrics. Both models show
substantial probability overprediction in many calibration bins, so the
probabilities should not automatically be interpreted as well-calibrated
real-world fire probabilities.

Full threshold sweeps, confusion matrices, and calibration tables are in
`docs/phase6-threshold-calibration.md`, generated by
`PYTHONPATH=. python -m ml.phase6`.

### Interpretation
The Phase 5 default-0.5 F1 ranking changes after selecting a threshold on
VALIDATION: Random Forest improves from 0.7082 to 0.7307 at threshold 0.65,
while Gradient Boosting improves from 0.6932 to 0.7340 at threshold 0.70.
Therefore the earlier Random Forest F1 advantage was not sufficient to
establish it as the better model.

Gradient Boosting is now the **preferred candidate** because it has the best
VALIDATION F1 after threshold selection and the best PR-AUC. The margin is
small, however, and Random Forest has better calibration metrics. This is a
candidate decision, not a claim that Gradient Boosting is universally the
better algorithm.

### Decision
**Preferred candidate: Gradient Boosting at threshold 0.70.**

**No final model selection has occurred yet.** The candidate and threshold
are based only on VALIDATION. TEST remains completely untouched and will be
evaluated exactly once after the final candidate/operating point is locked.

Calibration is imperfect for both models. A calibrated probability output
would require an additional validation-only calibration step before TEST if
probabilities themselves are a product requirement. Calibration should not
be introduced merely to improve the classification F1 number; the threshold
already provides the operating-point decision for classification.

### Final candidate lock

**Locked model:** Gradient Boosting (`HistGradientBoostingClassifier`)

**Locked threshold:** 0.70

The model and operating threshold were selected using VALIDATION only.
Gradient Boosting achieved the best validation F1 after threshold selection
(0.7340 at threshold 0.70) and the best PR-AUC (0.8176). Random Forest
achieved F1 0.7307 at threshold 0.65 and PR-AUC 0.8156.

Probability calibration is not included in the locked operating point because
the current product objective is binary fire-risk classification rather than
delivery of calibrated probability estimates.

**VALIDATION is now frozen. No further model, threshold, or calibration
selection will be performed using VALIDATION.**

The next evaluation is the single TEST evaluation of this locked model and
threshold. TEST has remained untouched throughout Phases 4–6.
